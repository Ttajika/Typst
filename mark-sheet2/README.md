# マークシート読み取り・採点システム（技術リファレンス）

Typst のマークシートテンプレート（`marksheeters.typ` / `template.typ`）と対になる読み取り・採点系の技術文書です。
**試験の作り方から採点までの通し手順は `マニュアル.md` を参照してください。** ここでは仕組み・調整・検証を扱います。

## 構成

| ファイル | 役割 |
|---|---|
| `marksheet.html` | **本番用。** ブラウザだけで読み取り・確認・訂正・採点まで完結する単一ファイル |
| `lib/marksheeters.typ` `lib/template.typ` | Typst テンプレート（座標・正答のメタデータ出力込み） |



---

## 1. 用紙情報の受け渡し

Typst の `context` 内では `query()` が使えるため、**組版し終えた自分の座標を自分で読んで、最終ページに文字として印刷**しています。格子が規則的なので全セルは書かず、設問行ごとの先頭座標＋刻み幅＋学籍番号の桁 x／選択肢 y＋四隅＋正答・配点・採点パターンだけを持ちます（48問で約1.5KB）。

PDF のテキスト抽出は**行の順序を保証しない**ため、`MS|通し番号|断片|` の形式で1行ずつ印刷し、読み取り側で並べ直します。

> **用紙情報ページには正答と配点が印刷されます。** 学生に配るのは解答用紙のページだけにしてください。
> このページ自体を出したくない場合は `project.with(layout-info: false)` とし、`layout.sh` で JSON を渡します。

> Typst 0.15 で `typst query` は非推奨になりました。`layout.sh` は
> `typst eval 'query(<markpos>).map(it => it.value)'` を先に試し、使えない環境では従来の
> `typst query` に落ちるので、どちらのバージョンでも動きます。

## 2. スキャンの設定

| 項目 | 設定 | 理由 |
|---|---|---|
| 色 | **グレースケール推奨** | 薄いマークが複合機の閾値で消える前の情報が残る |
| 解像度 | 200〜300 dpi | 300 推奨。それ以上は無駄 |
| 白紙除去 | **オフ** | ページと答案の対応がずれる |
| 枠消し（縁消去） | **オフ** | 四隅の丸が紙の端から約5mmにあり、ちょうど消される |
| 傾き補正 | どちらでも | 四隅から補正するので不要 |

**2値（白黒）スキャンでも動作します**（実スキャンで検証済み。塗りが十分濃ければ判定も通ります）。ただし複合機の閾値を下回ったマークは復元不能なゼロになるため、失敗は「無回答→要確認」として現れます。グレースケールならその手前の情報が残り、確認の手間が減ります。

## 3. 読み取りの仕組み

1. **ラスタライズ** — ページの長辺が「用紙の長辺×DPI」になるよう正規化（スキャナのページサイズに依存しない）
2. **四隅検出** — 画像の四隅18%の窓だけを連結成分ラベリングし、大きさ・縦横比・塗り量で丸を選ぶ
3. **天地判定** — 4通りの向きで「マーク欄予測位置のインク量」を比べ、最大の向きを採用（正解は他の約2倍のスコアになる）
4. **透視変換** — 四隅の対応4点からホモグラフィを解く。画像全体は変形せず、**セルごとに用紙座標→画像座標の逆写像**で濃度を取る
5. **ベースライン補正** — 未記入セルにも印字数字のインクがある（実測 0.22〜0.40、文字により差）。セルごとの基準値を引いてから判定する
6. **判定** — 行内の最大濃度セルを採用。薄い→無回答、2位が濃い→二重マーク、僅差→要確認
7. **学籍番号** — 桁ごとの argmax ではなく、**名簿の各 ID を「要求されるセルの平均濃度」で採点**して最良を選ぶ。信頼度は候補間の距離ではなくインクの明瞭さで判定（同一学科・学年が並ぶ名簿では似た番号が常に存在するため）
8. **採点** — `patterns` に従い、通常（0）／セット（2…8、全問一致で得点）／順不同（1…9、一致数×配点）

### ベースライン推定の要点

`--blank`（白紙スキャン）があればそれを使います。なければ答案の集合から推定しますが、単純な中央値は**正答セルが「塗られた状態」を基準にしてしまい全員無回答になります**。答案ごとに各群の突出セルを除いてから中央値を取り、それでも標本が残らないセル（**学年・学科コードの桁では必ず起きます**）は同じ文字が印字された他のセルから代用します。「全員が同じマークをした箇所があり…」という情報表示は正常動作です。

## 4. 確認・訂正（HTML 版）

- **全答案**の手書き氏名欄と学籍番号欄が並びます。名簿照合をすり抜ける誤読は名簿構成により 0.6〜3.7% 残り、学生自身のマークミスはアルゴリズムでは検出不能なので、**氏名欄との目視突き合わせが最後の防御**です
- 学籍番号の書き換え・要確認マークの選び直しは**その場で再採点**されます（採点ロジックがブラウザ内にあるため）。名簿にない番号は赤表示
- 項目分析（正答率・識別力＝点双列相関・選択分布）を同じ画面で表示。**識別力が負なら `answer:` の設定ミスをまず疑う**
- 出力は `scores.csv` と `item_analysis.csv`

### 読めないページの診断

読めなかったページは診断パネルに出ます：ページ縮小画像＋検出した塊の枠（緑＝採用候補、赤＝却下）、2値化閾値、期待する丸の直径と許容範囲、角ごとの候補テーブル（大きさ・面積・却下理由）。「診断情報をダウンロード」で `diagnostics.json` に数値を書き出せます。

| 診断の見え方 | 原因 | 対処 |
|---|---|---|
| その角に丸が写っていない | 枠消し設定・角折れ・端切れ・別のページ | 枠消しオフで再スキャン等 |
| 却下理由が全角一律に「小さすぎ/大きすぎ」 | 用紙情報が別の版（拡縮印刷含む） | 実際に刷った用紙と同じコンパイルの PDF を渡す |
| 却下理由「塗り不足」 | 丸の線がかすれて円環が途切れ | グレースケール・300dpi で再スキャン |
| ①と②の取り違え | 両方 PDF のため | ①=試験 PDF、②=答案スキャン |

## 5. 調整箇所（CONFIG）

HTML 版は「詳細設定」（解像度・塗り閾値）

| 項目 | 既定 | 説明 |
|---|---|---|
| `DPI` | 300 | ラスタライズ解像度 |
| `FILL_MIN` | 0.15 | ベースライン補正後の濃度がこれ以上なら「塗り」。薄いマークが無回答になるなら下げる |
| `MARGIN_MIN` | 0.10 | 1位と2位の差がこれ未満なら要確認 |
| `DOUBLE_MIN` | 0.20 | 2位もこれ以上なら二重マーク |
| `ID_SCORE_MIN` | 0.15 | 学籍番号7桁の平均濃度の下限 |
| `FID_SIZE_TOL` ほか | — | 四隅の丸の許容範囲。「見つからない」ときに広げる |
| `BASELINE_EXCL_GAP` | `None` | **`None` のまま推奨**（`FILL_MIN/2` に自動連動。固定値にすると薄いマーク時に推定が壊れる） |

**`FILL_MIN` を変えたら MARGIN/DOUBLE/ID も比例させること**（HTML 版は自動連動）。

## 6. 配布

渡すのは **`marksheet.html` ＋ 試験 PDF の2ファイル**です。受け取る側にインストールは一切不要で、
通信も発生しません（答案・名簿は相手の手元から出ません）。相手側の手順は `マニュアル.md` 第 IV 部を参照。

## 7. テンプレート側の機能（概要）

書き方の詳細は `マニュアル.md` 第 I 部を参照。読み取りに関わる要点のみ：

- `layout-info: true`（既定）— 用紙情報ページを末尾に出す
- `answer-breaks: auto` — `mondai` の位置から解答用紙に大問の区切り帯を自動挿入。`answer-labels: true` で大問名の帯も表示。区切りは `hline` ではなくセル内の線として引くため**外枠からはみ出さない**（`hline` は線幅の半分が構造上はみ出る）
- `#mark-rei()` — 記入例（良い例・悪い例）の凡例
- `setmon(note: [...])` ＋ `show-kaisetsu: true` — 解説一覧ページ
- **区切り帯・ラベル帯は行として挿入されるため座標が動きます。** 用紙と用紙情報は必ず同じコンパイルから取ること（PDF 埋め込み方式なら自動的に満たされます）
